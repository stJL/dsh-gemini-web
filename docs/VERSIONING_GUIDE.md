# 版本号管理规范 (Semantic Versioning Guide)

本规范遵循国际通用的 **SemVer 2.0.0 (Semantic Versioning)** 标准，专为 `dsh-gemini-web` 外挂专案量身定制，用于清晰界定公测期（Public Beta）与正式版各个阶段的版本演进规则。

---

## 1. 版本号结构

标准版本号格式为：`MAJOR.MINOR.PATCH`（主版本号 . 次版本号 . 修订号）

```text
    0  .  1  .  1
    │     │     │
    │     │     └── PATCH (修订号)：向下兼容的小型缺陷修复、文案调优与健壮性补充
    │     └──────── MINOR (次版本号)：向下兼容的新功能增加、功能模块大幅扩展
    └────────────── MAJOR (主版本号)：突破性架构升级、不向下兼容的破坏性变更
```

---

## 2. 公测期（0.x.y 阶段）演进规则

> [!NOTE]
> 根据 SemVer 规范，`0.y.z` 明确代表专案当前处于**公开测试 / 快速迭代期 (Public Beta)**。
> 在此阶段，核心架构与介面仍在根据用户真实反馈快速打磨。

| 变更类型 | 版本变动示例 | 触发条件与适用场景 | 对应 Git Commit 前缀 |
| :--- | :--- | :--- | :--- |
| **Patch (修订号)** | `0.1.0` ➜ `0.1.1` ➜ `0.1.2` | • 修复错误、防假死熔断机制、通道断线检测<br>• 文案调整、多语言翻译（i18n）补全<br>• 样式/布局自适应优化、小修小补 | `fix:`、`docs:`、`style:`、`refactor:` |
| **Minor (次版本号)** | `0.1.x` ➜ `0.2.0` ➜ `0.3.0` | • 新增全新的完整功能（如新增全新调度策略、接入新站点）<br>• 设置大盘新增全新的配置模块 | `feat:` |

---

## 3. 何时正式发布 1.0.0 (生产发布里程碑)

当专案满足以下 **三大里程碑** 时，正式宣布脱离 Public Beta，迈入 `1.0.0` 正式版时代：

1. 📦 **NPM 官方源正式上架**：成功发布至 `registry.npmjs.org`，支援社群直接通过 `pnpm add dsh-gemini-web` 一键安装。
2. 🔄 **上游同步多轮实战检验**：经历过原作者（`gemini-web-agent`）至少 2~3 次更新迭代，自动同步脚本与相容性测试平稳运作。
3. 🛡️ **跨平台与多浏览器长期稳定**：在 Chrome / Edge / Brave 以及各主流操作系统（Linux、macOS、Windows）上经社群实测无重大阻断性缺陷。

---

## 4. 正式版（>= 1.0.0 阶段）规则

进入 `1.0.0` 之后，严格遵守以下铁律：
* **PATCH (`1.0.x`)**：只允许向下相容的 Bug Fixes，绝不改变任何已有设定项。
* **MINOR (`1.x.0`)**：新增向下相容的功能特性，旧版使用者无需修改任何配置即可无缝使用。
* **MAJOR (`x.0.0`)**：当出现**不向下相容的破坏性变动**（例如 DSH 核心架构重构导致旧版配置完全失效）时，才允许将主版本号晋升为 `2.0.0`。

---

## 5. 版本发布核对清单 (Release Checklist)

每次准备发版时，仅需 4 步极简核对：

1. **更新 `package.json`**：将 `"version": "x.y.z"` 改为目标版本号。
2. **更新前端徽章**：在 `client.js` 标题栏微调版本标识（如 `'vx.y.z'`）。
3. **重新打包建置**：执行打包指令，确保 `index.js` 产物最新：
   ```bash
   npm run build
   ```
4. **提交并打 Tag**：
   ```bash
   git add package.json client.js index.js
   git commit -m "chore(release): bump version to x.y.z"
   git tag vx.y.z
   git push && git push --tags
   ```
